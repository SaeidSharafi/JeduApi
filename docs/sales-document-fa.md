# بخش‌های ۳، ۴ و ۵ — مستند فروش جدو شاپ

**بازبینی فنی:** ۸ اوت ۲۰۲۶

**نوع سند:** معرفی محصول؛ این فایل قرارداد فنی، API یا گزارش قطعی پیشرفت نیست.

اطلاعات بک‌اند این سند با مخزن فعلی تطبیق داده شده است. وضعیت فرانت‌اند، زمان تحویل، ظرفیت عملیاتی و شاخص‌های عملکرد باید پیش از ارائه تجاری از مخزن و محیط همان نسخه تأیید شوند.

## ۳. ویژگی‌های فنی و تجربه کاربری

### فرانت‌اند

معماری هدف برای وب‌سایت فروشگاهی، رابط مستقل مبتنی بر Next.js و رندر سمت سرور است تا صفحات عمومی قابلیت مناسب SEO داشته باشند. کد فرانت‌اند در این مخزن نگهداری نمی‌شود؛ بنابراین موارد زیر معیار تحویل هستند، نه ادعای تکمیل‌شدن:

- متادیتای مستقل و داده ساخت‌یافته برای صفحات عمومی
- طراحی Mobile-First و دسترس‌پذیر
- سناریوهای E2E برای احراز هویت، جستجو، سبد خرید، پرداخت و دسترسی پس از خرید
- گزارش قابل تکرار Lighthouse و بررسی فنی SEO روی نسخه تحویلی

### بک‌اند

بک‌اند یک API مستقل برای فروش و تحویل محصولات آموزشی است. قابلیت‌های شاخص پیاده‌سازی‌شده در مخزن فعلی:

- کاتالوگ چندلایه برای دوره، سمینار، فایل دیجیتال، محصول تجاری و گزینه تحویل
- سبد خرید، سفارش، رزرو ظرفیت، پرداخت و بازپرداخت
- پرداخت کیف پول، انتقال بانکی، بانک ملت و Digipay
- موتور تخفیف سبد خرید و قیمت‌های تخفیفی پیش‌محاسبه‌شده
- کیف پول با دفتر تراکنش، قفل همزمانی و کنترل تکرار عملیات
- فعال‌سازی صف‌بندی‌شده در IMS، Moodle، SpotPlayer، BigBlueButton و Skyroom
- جستجو با Typesense و fallback پایگاه داده
- احراز هویت Sanctum، OTP و کنترل دسترسی کارکنان
- مستندسازی API از قراردادهای DTO با Scribe

اطلاعات حساس یکپارچه‌سازی‌ها در لایه تنظیمات مدیریت می‌شوند. مسیرهای مالی و فعال‌سازی دسترسی از Actionها، سرویس‌های دامنه، رویدادها و jobهای صف استفاده می‌کنند؛ controller نباید محل منطق تجاری باشد.

## ۴. معماری و زیرساخت فنی

| بخش | وضعیت فنی مخزن بک‌اند |
|---|---|
| Runtime | PHP 8.4 / Laravel 12 |
| API contracts | Spatie Laravel Data / Scribe |
| Authentication | Laravel Sanctum |
| Authorization | Spatie Laravel Permission و Policy/Gate |
| Queue operations | Laravel Horizon |
| Search | Laravel Scout، Typesense و fallback پایگاه داده |
| Testing | Pest 4 |
| Development environment | Docker / Laravel Sail |

پایگاه داده مرجع PostgreSQL است و پروژه برای بخش‌هایی از منطق داده، مسیرهای سازگار با MySQL نیز دارد. ادعای پشتیبانی کامل از یک موتور پایگاه داده فقط پس از اجرای migrationها و مجموعه تست همان نسخه معتبر است.

## ۵. وضعیت عرضه و تحویل

درصد پیشرفت ثابت در این سند نگهداری نمی‌شود، چون به‌سرعت قدیمی و گمراه‌کننده می‌شود. وضعیت هر عرضه باید از یک نسخه مشخص، نتایج CI، migrationها، مستندات تولیدشده API و آزمون پذیرش همان محیط تهیه شود.

### چک‌لیست پیش از اعلام آمادگی نسخه

- نسخه یا commit مورد ارزیابی مشخص باشد.
- migrationها و تست‌های بک‌اند روی محیط هدف موفق باشند.
- مستندات Scribe از همان نسخه تولید و بازبینی شده باشند.
- درگاه‌های فعال با تنظیمات sandbox یا پذیرش عملی تأیید شوند.
- queue workerها، scheduler، مانیتورینگ و پشتیبان‌گیری محیط بررسی شوند.
- فرانت‌اند با قرارداد API همان نسخه آزمون E2E شود.
- شاخص‌های SEO، Lighthouse، ظرفیت و زمان پاسخ با گزارش قابل بازتولید ارائه شوند.

زمان تحویل و دامنه نسخه اولیه پس از تعیین نسخه مبنا، محیط مقصد و معیارهای پذیرش اعلام می‌شود.
