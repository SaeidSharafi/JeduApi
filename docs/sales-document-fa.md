# بخش‌های ۳، ۴ و ۵ — مستند فروش جدو شاپ

## ۳. ویژگی‌های فنی و UX

### فرانت‌اند

فرانت‌اند با **Next.js** و به صورت **Server-Side Rendering (SSR)** پیاده‌سازی می‌شود. این انتخاب به دلیل الزامات SEO است؛ صفحات به جای رندر در مرورگر، از سمت سرور تولید می‌شوند و برای خزنده‌های موتورهای جستجو قابل خواندن هستند.

**استانداردهای SEO:**
- عنوان (title) و متا دیسکریپشن مجزا برای هر صفحه
- نشانه‌گذاری داده‌های ساختاریافته با schema.org
- بهینه‌سازی خودکار تصاویر از طریق Next.js Image Optimization

**عملکرد و دسترسی:**
- طراحی Mobile-First؛ سایت روی تمام اندازه‌های صفحه به درستی نمایش داده می‌شود
- هدف امتیاز حداقل ۹۰ در Google Lighthouse برای تمام صفحات اصلی

**تست و تحویل:**
- پیاده‌سازی و تأیید ۱۰ سناریوی E2E خودکار برای فلوهای اصلی کاربری
- تحویل پروژه در قالب استاندارد Next.js به همراه مستندات
- ارائه گزارش تست از ابزارهای Google Search Console، Lighthouse، و Screaming Frog

---

### بک‌اند

**API و مستندات:**
- تمام endpointها با Scribe مستند شده‌اند، شامل نمونه request و response برای هر endpoint
- سه گروه endpoint کاملاً مجزا: پنل ادمین، فروشگاه (نیاز به لاگین)، و عمومی

**کش و عملکرد:**
- محتوای صفحه اصلی و نتایج جستجو با استراتژی stale-while-revalidate کش می‌شوند؛ کاربر همیشه پاسخ فوری دریافت می‌کند و به‌روزرسانی در پس‌زمینه انجام می‌شود
- تغییر هر محتوا به صورت خودکار کش مرتبط را باطل می‌کند
- قیمت‌ها پیش‌محاسبه‌شده ذخیره می‌شوند تا فیلتر و مرتب‌سازی روی قیمت بدون کوئری سنگین انجام شود

**پردازش غیرهمزمان:**
- فعال‌سازی دسترسی در پلتفرم‌های خارجی (Moodle، SpotPlayer، BBB، IMS) به صورت job صف‌بندی‌شده با retry خودکار انجام می‌شود
- تغییر وضعیت پرداخت و ثبت‌نام از طریق رویداد مدیریت می‌شود، نه منطق مستقیم در controller
- task‌های زمان‌بندی‌شده: انتشار خودکار پست‌های بلاگ، شناسایی پرداخت‌های معلق، پاکسازی قیمت‌های ویژه منقضی‌شده

**امنیت:**
- credential‌های اتصال به سرویس‌های خارجی رمزنگاری‌شده در دیتابیس ذخیره می‌شوند و هرگز در خروجی API نمایش داده نمی‌شوند
- تمام endpointهای ادمین با سیستم Policy بررسی مجوز می‌شوند
- تأیید پرداخت idempotent است؛ callback تکراری درگاه تأثیری ندارد و ثبت‌نام مجدد ایجاد نمی‌شود
- تست‌های feature روی PostgreSQL در CI اجرا می‌شوند

## ۴. معماری و زیرساخت فنی

### تکنولوژی‌ها

| بخش | تکنولوژی |
|-----|----------|
| Frontend | Next.js (SSR) |
| Backend | Laravel 12 / PHP 8.4 |
| Database | PostgreSQL (اصلی) — MySQL نیز پشتیبانی می‌شود |
| Queue | Laravel Horizon |
| Search | Typesense با fallback به SQL full-text |
| Authentication | Laravel Sanctum |
| Authorization | Spatie Laravel Permission |
| Storage | S3 / Local |
| Testing (Backend) | Pest 4 |
| Testing (Frontend) | E2E Automated Tests |

### الگوی معماری

کد بک‌اند از الگوی **Action/Service** پیروی می‌کند. هر عملیات تجاری در یک کلاس مجزا قرار دارد و controllerها هیچ منطقی را مستقیم اجرا نمی‌کنند. این ساختار نگهداری، توسعه موازی، و تست‌نویسی مستقل را ساده‌تر می‌کند.

قراردادهای API با DTOهای type-safe تعریف شده‌اند؛ هم validation و هم مستندسازی از همان کلاس خوانده می‌شوند که یک منبع واحد برای تعریف هر endpoint فراهم می‌کند.

### Backend — ۹۰٪

**تکمیل‌شده:**
- کاتالوگ محصول (دوره، وبینار، محتوای دیجیتال) با مدیریت کامل
- سیستم سفارش، پرداخت، و ثبت‌نام دانشجو
- درگاه بانک ملت، پرداخت کیف پول، و انتقال بانکی
- موتور تخفیف و کوپن
- فعال‌سازی دسترسی در Moodle، SpotPlayer، BBB، و IMS
- سیستم نقش و دسترسی ادمین
- CMS شامل بلاگ، اسلایدر، بلوک‌های صفحه اصلی، و تنظیمات
- جستجوی متنی
- کیف پول و کمپین‌های اعتبار
- لاگ اکشن‌های ادمین
- سیستم نظردهی

**باقی‌مانده:**
- تکمیل برخی endpointهای گزارش‌گیری
- بهینه‌سازی تحت بار واقعی
- پوشش تست بیشتر برای integrationهای جدید

### Frontend — ۶۰٪

API کاملاً مستند است و قراردادها پایدار هستند. توسعه فرانت‌اند بر اساس همین APIها در جریان است.

**تکمیل‌شده:**
- صفحات اصلی فروشگاه (لیست و جزئیات محصول)
- جریان احراز هویت (OTP و رمز عبور)
- سبد خرید و صفحه پرداخت
- پروفایل کاربر و لیست دوره‌های خریداری‌شده
- بخش‌هایی از پنل ادمین

**باقی‌مانده:**
- UX نهایی صفحه پرداخت و تأیید سفارش
- بخش‌های مدیریت تخفیف، کیف پول، کمپین، و لاگ در پنل ادمین
- داشبورد دانشجو برای مشاهده پیشرفت و دسترسی به پلتفرم‌های خارجی
- پیاده‌سازی و تأیید ۱۰ سناریوی E2E خودکار
- بهینه‌سازی Lighthouse و تست SEO نهایی
