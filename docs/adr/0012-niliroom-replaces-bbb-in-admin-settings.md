# Niliroom replaces BBB as the admin-configurable live-session provider

The admin settings area for provisioning providers lists a provider only when its credentials belong in that form. BBB's configuration (`base_url`, `secret`, `api_path`, attendee/moderator passwords) is dropped from that surface and Niliroom (`enabled`, `base_url`, `api_token`) takes its place, because Niliroom is the panel the platform is moving to and the settings screen should describe where we are going, not the legacy fallback. An empty Niliroom record is harmless while the Niliroom adapter does not exist yet: it is a stored configuration row the panel can fill in before the service lands.

> Status update: the adapter has since landed as `NiliroomService` (issue #54), so the record is no longer inert. `ProvisioningProviderSettingsEnum::NILIROOM::serviceClass()` now names it, and `ProvisioningProviderSettingsAgreementTest` compares the panel's schema-derived `configured`/`ready` badge with the adapter's own `assertConfigured()`/`isReady()` like every other provider.
>
> Superseded in part by ADR 0013: the paragraph below that keeps `BbbService` alive as an environment-configured fallback no longer stands — Niliroom replaces BBB entirely and the BBB delivery path is retired (#113). The consequence below about `BbbService`'s `default_attendee_pw` / `default_moderator_pw` read is moot for the same reason: the service is deleted, so there is no mismatch left to correct and no student join path depending on those passwords. Keeping BBB off the admin surface, which is this ADR's actual decision, still holds.

This retires the admin surface only. `BbbService`, `config/services.bbb`, `SettingKeyEnum::BIG_BLUE_BUTTON` and `ProvisioningProviderEnum::BBB` stay alive, so the student join path and ADR 0007's fallback keep working — configured by deployment environment instead of by an admin form. Retiring the BBB delivery path itself is a separate decision that cannot be taken before the Niliroom adapter ships, because a `live_session_niliroom` seminar would otherwise have no join URL at all.

Consequences: ADR 0007's Niliroom-primary decision is unchanged, but its BBB fallback is now environment-configured rather than admin-editable. `BbbService`'s read of `default_attendee_pw` / `default_moderator_pw` (while config, seeder and redactor say `*_password`) must still be corrected, since the student join path depends on those passwords and the admin form no longer reveals the mismatch.
